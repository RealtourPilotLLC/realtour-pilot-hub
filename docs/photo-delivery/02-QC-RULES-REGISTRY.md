# Realtour Pilot QC Rules Registry

> Generated from `qc-rules.seed.json` by `gen_registry_md.py`. Do not edit by hand: change the JSON (the source of truth) and regenerate. The checklist it encodes is `03-QC-CHECKLIST.md`.

## How the Ops Hub uses this registry

The Ops Hub QC engine loads `qc-rules.seed.json` at runtime (seeded into the database, versioned, and editable per client without a deploy). For each finished photo, Pass 1 first classifies the room type, then filters the registry to rules whose `pass` is `P1_PHOTO` and whose `rooms` include that room type or a scope group that contains it (minus `excludeRooms`). The engine runs the CV and METADATA rules in Node with sharp, then injects the applicable vision rules (id, `checklistText`, `visionHint`, severity conditions) into the vision prompt and asks the model to answer by rule id with a bounding box, confidence, and the escalation or de-escalation condition it matched. P2_GALLERY rules run once over the gallery, P3_COMPARE rules run on edited and original pairs when originals exist, and P4_ORDER rules run against Aryeo order data and pipeline state. Each finding maps back to its rule by id to get severity, `fixStrategies` (with `autohdrTransform` and `reeditPromptTemplate` for AutoHDR), responsibility, post-fixability, and reshoot guidance, and findings that share a `groupKey` across photos become one ticket.

### Engine conventions

- **Room filtering.** A rule applies to a photo when the photo's room type is listed in `rooms` (directly or via a scope group) and is not in `excludeRooms`. For P2_GALLERY rules, `rooms` limits which photos are compared (`GALLERY` means all). P4_ORDER rules are always scoped to `ORDER`.
- **Severity resolution.** Start at `defaultSeverity`. If the model or CV reports the `escalateTo.when` condition, use the escalated tier; if it reports the `deescalateTo.when` condition, use the lower tier. CV thresholds in `cvHint` are starting values to calibrate on real galleries.
- **Deduplication.** Findings with the same `groupKey` in one gallery become one ticket that lists every affected photo. If two rules with the same `groupKey` fire on the same photo (for example a general section 1 rule and a room-specific rule), keep the room-specific rule (higher section number). Several general section 1 rules also use `excludeRooms` so that room-specific rules own those rooms.
- **Auto-fix.** `autoFixEligible` marks rules whose fix is low risk. By default every fix still waits for a decision in the Fix Cart (proceed, ignore, or select). Auto-fix runs only when the optional auto-fix setting is on (default off), the live AutoHDR price for the fix is 0 credits, the finding is not CRITICAL, and confidence is at least 0.9. Every fixed photo is re-inspected (P1, plus P3 against the pre-fix version) before the finding closes. Auto-fix never means auto-deliver: any CRITICAL finding still needs human sign-off.
- **Permanent features.** When `permanentFeatureRisk` is true, `HUMAN_REVIEW` is always the first fix strategy, and no AI edit or revert runs until a person approves it (checklist section 13 critical rule).
- **Color truth.** Material color rules never auto-fix by guessing. They compare against originals in P3 (`VISION_COMPARE`) or route to `HUMAN_REVIEW` for editor or photographer verification (checklist section 11).
- **Reshoots.** `RESHOOT` is only ever a recommendation shown to an admin. The engine never orders one (checklist section 22).
- **AutoHDR twilight.** Rules about virtual twilight list `REVERT_VERSION` then `EDITOR_MANUAL` with `autohdrTransform: twilight`, meaning: revert to the pre-twilight version, then re-run the twilight transform or hand it to the editor.

## Types

```ts
type Severity = 'CRITICAL' | 'MAJOR' | 'MINOR';
type Pass = 'P1_PHOTO' | 'P2_GALLERY' | 'P3_COMPARE' | 'P4_ORDER';
type Detector = 'VISION_PHOTO' | 'VISION_GALLERY' | 'VISION_COMPARE' | 'CV' | 'METADATA' | 'ORDER_DATA' | 'WORKFLOW';
// CV = deterministic image analysis in Node (sharp): blur (Laplacian variance), exposure histogram clipping,
//      dust blob detection + cross-image recurrence, perceptual hash duplicates, color stats (Lab means), dimensions.
// METADATA = EXIF/file checks (format, dimensions, decode, drone make DJI, GPS, watermark flag from pipeline).
// ORDER_DATA = Aryeo order items / listing beds-baths / client instructions / hub product map.
// WORKFLOW = pipeline state, revision records, version tracking, upload verification.
type Responsibility = 'PHOTOGRAPHER' | 'EDITOR' | 'ADMIN' | 'HUMAN_REVIEW';
type RoomType =
  | 'EXTERIOR_FRONT' | 'EXTERIOR_REAR' | 'EXTERIOR_SIDE' | 'AERIAL' | 'TWILIGHT_EXTERIOR' | 'PATIO_DECK'
  | 'POOL_SPA' | 'YARD' | 'COMMUNITY_AMENITY' | 'ENTRY_FOYER' | 'LIVING' | 'FAMILY' | 'DINING' | 'KITCHEN'
  | 'OFFICE' | 'BEDROOM' | 'PRIMARY_BEDROOM' | 'BATHROOM' | 'PRIMARY_BATHROOM' | 'POWDER_ROOM' | 'LAUNDRY'
  | 'GARAGE' | 'BASEMENT_FINISHED' | 'BASEMENT_UNFINISHED' | 'STORAGE' | 'HALLWAY' | 'STAIRCASE' | 'CLOSET'
  | 'DETAIL' | 'OTHER';
type RoomScope = 'ANY' | 'INTERIOR' | 'EXTERIOR' | 'WET_ROOMS' | 'BATHROOMS' | 'BEDROOMS' | 'LIVING_SPACES'
  | 'UTILITY' | 'GALLERY' | 'ORDER';
type FixStrategy =
  | 'AUTOREMOVE_MASK'  // AutoHDR `autoremove`; mask PNG generated from the finding's bounding box (REST only)
  | 'DECLUTTER'        // AutoHDR `declutter` (whole photo, removes bins and loose items)
  | 'REEDIT_PROMPT'    // AutoHDR `reedit` with a natural-language prompt (optional mask)
  | 'CAMERA_REMOVAL'   // AutoHDR `camera_removal` (photographer/camera/tripod in mirrors or glass; refunded if no-op)
  | 'GRASS'            // AutoHDR `grass` (lawn greening)
  | 'STYLE_RERENDER'   // AutoHDR `style` with another model_id (re-renders from originals)
  | 'REVERT_VERSION'   // AutoHDR setPhotoVersion back to an earlier version (free; undo a bad AI edit)
  | 'EDITOR_MANUAL'    // human editor in Lightroom/Photoshop
  | 'RESHOOT'          // photographer reshoot (NEVER auto-ordered; admin decides)
  | 'ADMIN_ACTION'     // admin fixes data, uploads, order, file selection
  | 'HUMAN_REVIEW'     // human decision required; no automated fix offered
  | 'NONE';            // informational only
type AutohdrTransform = 'autoremove' | 'declutter' | 'reedit' | 'camera_removal' | 'grass' | 'style'
  | 'twilight' | 'single_angle_staging';

interface QcRule {
  id: string;                    // stable SCREAMING_SNAKE id with section prefix
  section: number;               // 1..18
  sectionName: string;
  checklistText: string;         // exact bullet text from 03-QC-CHECKLIST.md
  shortLabel: string;            // <= 40 chars, UI badge label
  rooms: (RoomType | RoomScope)[];
  excludeRooms?: (RoomType | RoomScope)[];
  pass: Pass;
  detector: Detector;
  secondaryDetector?: Detector;
  defaultSeverity: Severity;
  escalateTo?: { severity: Severity; when: string };
  deescalateTo?: { severity: Severity; when: string };
  fixStrategies: FixStrategy[];  // primary first, then fallbacks
  autohdrTransform?: AutohdrTransform | null;
  reeditPromptTemplate?: string;
  responsibility: Responsibility;
  postFixable: 'YES' | 'NO' | 'SOMETIMES';
  reshootPossible: boolean;
  permanentFeatureRisk: boolean; // true: HUMAN_REVIEW before any AI edit
  autoFixEligible: boolean;      // true only for low-risk removals and reversible state changes
  buildPhase: 1 | 2 | 3;
  priorityRank?: number;         // 1..18 from checklist section 23
  groupKey: string;              // dedup key across photos
  visionHint?: string;           // for VISION_* detectors
  cvHint?: string;               // for CV / METADATA detectors
}
```

- `SKY_HOUSE_EDGES_BLENDING` (House edges blend into sky): group `SKY_MASKING`. Vision: Flag light-colored rooflines, siding, or trim that dissolve into a bright sky with no defined edge. Do not flag soft edges caused only by distance or haze.

- `SKY_HALOS_TREES_ROOFLINES` (Sky halos): group `SKY_HALOS`. Vision: Flag bright or dark glowing outlines around trees, rooflines, or wires where the replacement sky meets the scene. Do not flag a natural backlit rim on foliage.
- `SKY_BLEEDING_INTO_WINDOWS` (Sky bleeds into windows): group `SKY_MASKING`. Vision: Flag replacement sky showing inside window panes or glass doors where an interior, a curtain, or a reflection should be. Do not flag natural reflections of the real sky that match the scene.
- `SKY_UNNATURAL_TRANSITIONS` (Unnatural sky transition): group `SKY_MASKING`. Vision: Flag hard cut lines, color fringes, or mismatched blur where the sky meets trees and the house. Do not flag natural depth-of-field softness in distant trees.
- `SKY_MISMATCHED_LIGHTING` (Sky/house lighting mismatch): group `SKY_REALISM`. Vision: Flag skies whose light direction, color temperature, or brightness contradicts the house (bright sunny sky over a flat, overcast-lit house; sun position inconsistent with shadows). Do not flag partly cloudy scenes with uneven natural light.
- `SKY_UNREALISTIC_SUNSET` (Unrealistic sunset): group `SKY_REALISM`. Vision: Flag sunset or dusk skies with implausible color (neon pink, purple-green gradients) or colors that do not light the house. Do not flag a real vivid sunset captured on site.
- `SKY_EXCESSIVELY_DRAMATIC` (Overly dramatic sky): group `SKY_REALISM`. Vision: Flag stormy, heavily textured, or HDR-crunched skies that overpower the house. Do not flag pleasant scattered clouds.

Starting values, calibrate.

### Section 22: Automation behavior and guardrails

| Guardrail | How the registry and engine enforce it |
|---|---|
| Prioritize objective defects over subjective styling preferences | Staging and composition rules default to MINOR and are never auto-fixed; objective defects (dust, blur, privacy, wrong files, missing deliverables) carry MAJOR or CRITICAL. |
| Use room-aware rules rather than applying every rule to every room | `rooms` and `excludeRooms` on every rule; the engine injects only the rules that match the P1 room label. |
| Do not automatically fail photographs simply because normal household objects exist | Each `visionHint` names what not to flag; `deescalateTo` drops small, background, or ordinary-storage items to MINOR (section 6 exception). |
| Distinguish permanent features from removable clutter | `permanentFeatureRisk` marks rules where a fix could reconstruct a permanent feature; those start with `HUMAN_REVIEW`, and hints list permanent look-alikes (vent, outlet, central-vac inlet, built-in dispenser). |
| Never assume an actual defect may be digitally concealed without approval | Dark spots that look physical, pool water condition, mirror desilvering, and removed stains or cracks route to human review (REFL_DARK_SPOTS_FLAT_SURFACES, EXT_POOL_DEBRIS, BATH_MIRROR_WATER_STAINS, AIEDIT_PERMANENT_FEATURES_REMOVED). Cleaning edits are never auto-fix. |
| Never assume an AI-generated replacement is accurate | Every AutoHDR result goes through Post-Fix Verification against the pre-fix version (section 13 rules) and a P1 re-run before the finding closes. |
| Compare RAW files when material colors or architectural details are uncertain | Color-truth and architecture rules run in `P3_COMPARE` with `VISION_COMPARE`; without originals they report the finding as uncertain and route it to the photographer or editor. |
| Do not treat a confidence score as proof | Findings below the display floor (0.5) go to a Low confidence drawer and never block delivery; the optional auto-fix needs `autoFixEligible`, a 0-credit price, non-CRITICAL severity, and confidence of at least 0.9. |
| Allow manual overrides with documented reasons | Finding status OVERRIDDEN requires reason text and the user id; rules can be disabled per client in the database copy of the registry. |
| Use property-specific instructions to determine exceptions | `ORDER_DATA` as a secondary detector on lifestyle-people, fireplace-fire, and amenity rules; client instructions are added to the P1 prompt. |
| Flag uncertain findings instead of presenting them as facts | Hints tell the model to report uncertainty (color truth, coverage, privacy legibility); low-confidence findings are shown separately in a Low confidence drawer. |
| Do not automatically order reshoots based solely on AI judgment | `RESHOOT` is a recommendation only and is never executed by the engine; an admin decides. |
| Do not automatically deliver galleries containing unresolved critical issues | Any open CRITICAL finding holds delivery (FILE_NO_DELIVERY_BEFORE_CRITICAL_REVISIONS); auto-fixed CRITICAL findings still need human sign-off. |
| Avoid requiring human approval for every minor preference | MINOR findings are nonblocking and never need approval. With the optional auto-fix setting on, zero-credit eligible fixes run without approval; everything else is one click in the Fix Cart. |
| Track recurring defects by photographer, editor, property, and issue category | Findings store photographer id, editor id, property id, `section`, and `groupKey`; `responsibility` says who should prevent the repeat. |
| Preserve the original files for reference | AutoHDR edits create new versions and originals are never overwritten, which is what makes `REVERT_VERSION` and P3 possible. |
| Record which checks were performed and which were skipped because data was unavailable | Each QC run stores the rule ids evaluated per photo and the ids skipped with a reason (no original for P3, no order data for P4, decode failure). |
